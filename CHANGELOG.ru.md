## v1.7.0 — 2026-08-12

Необязательный второй взгляд Codex, встроенный в конвейер:

- **Новое: `skills/pf-do/scripts/codex-review.sh`** — ревью текущего диффа локальным Codex CLI в режиме read-only. Полный отчёт уходит в файл (`workspace/runs/codex-review/`), в контекст агента попадает выжимка ~6 строк: ревью стоит минут по времени и почти ничего по окну.
- **Ничего не обязательно.** Четыре молчаливых гейта, каждый с кодом возврата 0: нет `codex` в PATH → нет согласия проекта (`.agents/codex-review.json`) → не git-репозиторий или пустой дифф → в диффе только проза и lock-файлы. Без установленного Codex конвейер работает ровно как раньше — это замысел, а не запасной путь.
- **Крючки:** `pf-do` шаг 5a (перед `status: review`), `pf-auto` — пре-пасс перед гейтом вехи (`--deep`, ревьюера-субагента не заменяет), `pf-spec` шаг 4a — единственный вопрос о согласии, задаётся при написании спеки и только если `codex` есть на машине, `pf-handoff` шаг 2a (инструмент-компаньон) — при закрытии сессии с незакоммиченным кодом.
- **`pf-do/references/codex-review.md`** — памятка: два режима ревью и почему фокусный прогон не может пользоваться родным ревьюером, политика моделей (`gpt-5.6-luna`/`max` — быстрая полоса, `gpt-5.6-sol`/`xhigh` — тяжёлая, `ultra` запрещён), и грабли: `codex exec review` всегда возвращает 0, пустой отчёт означает смерть прогона, `codex exec` без `</dev/null` висит вечно.
- **Почему это ревью не отменяет §6:** родной ревьюер Codex формулирует задачу сам, поэтому слепая зона вызывающего в промпт не попадает — но работает он на той же машине с тем же репозиторием. Это дешёвая половина проверки, а не независимый аудит.

Восемь дефектов самого инструмента найдены и починены до релиза, шесть из них — ревью Codex по этому же скрипту: флаг без значения вешал разбор аргументов в вечный цикл; `--deep` не перебивал fast-lane из конфига проекта; конфиги, CI-workflow и схемы отфильтровывались как «документация»; в фокусном режиме untracked-файлы оставались невидимы; недоступный `--out` рапортовал «OK, 0 находок»; сторож слал один SIGTERM без добивания; `-s` не отличал каталог от файла (второй путь ложно-чистого вердикта); сторож убивал обёртку-subshell вместо самого Codex.

## v1.6.0 — 2026-08-12

Скиллы переписаны на английском:

- Тела инструкций всех шести скиллов (`pf-spec`, `pf-tickets`, `pf-do`, `pf-replan`, `pf-retro`, `pf-auto`) и инструктивные references (`dispatch-templates`, `maturity-scale`) теперь на английском — ≈35–45% меньше токенов при каждой загрузке скилла, плюс читаемость для международной аудитории. Триггер-фразы в descriptions остались двуязычными.
- **Описание скилла начинается с русской фразы.** В `description` каждого скилла первой идёт короткая русская фраза «что и зачем», английский текст — следом: список скиллов человек читает глазами, а после перевода на английский этот список перестал говорить на его языке. `pf-retro` заодно получил недостающие русские триггер-фразы. На ведущую фразу ничто в логике скилла не опирается — для одноязычной сборки её достаточно удалить.
- Контракты поведения не изменились: статусы пакетов, имена разделов («Результат» и др.), формат журнала и протокольные литералы промптов pf-auto сохранены дословно. Шаблоны артефактов (`spec-template`, `task-template`, `registry-template`, `retro-template`) намеренно остались русскими — артефакты исходной системы русские; замените своим языком при необходимости. Скиллы теперь явно велят агенту отвечать на языке пользователя.
- Проверено до релиза: триггер-тест из 20 русских фраз (2 прогона до / 2 после, совпадение 80/80, включая несущие фразы автопилота §8) и живой прогон исполнителя — язык вывода и форматы артефактов не изменились.

## v1.5.0 — 2026-08-11

Находки второго изолированного прогона (краевые случаи, а не «счастливый путь»):

- **pf-do**: сделанное до блокера теперь тоже коммитится (`T-###: blocked — сохраняю сделанное`) — незакоммиченный «хвост» ломает дифф следующего гейта и теряется при смене сессии; доказательство в «Результате» должно быть выводом команды, а не пересказом (в прогоне заявлено «4 предложения» там, где их 3 — поймал гейт вехи).
- **pf-do / pf-auto**: тикет, которому нужен секрет, — сразу блокер: субагенты и headless-запуски не могут вызвать хелпер секретов. Такие тикеты не гоняются по фикс-циклу, помечаются «нужна интерактивная сессия» и, если известно заранее, не попадают в волны.
- **pf-auto**: проверка чистоты рабочего дерева между волнами.
- Проверено в песочнице: гейт по вехам (один ревьюер на три независимых задания — поймал ложное доказательство), поведение исполнителя при противоречивых критериях / отсутствующем исходнике / недоступном секрете (три корректных BLOCKED, ничего не выдумано) и непрерывность оркестратора — преемник, получивший только HANDOFF, восстановил цель, реестр, точный следующий шаг и блокеры, и заметил незакоммиченный хвост, который пропустил оркестратор.

## v1.4.0 — 2026-08-10

- **Гейты pf-auto теперь по риску** (`gate = auto`): гейт после каждого задания, если задания строят друг на друге или правят исполняемое (код, конфиги, схемы данных, скрипты, инфраструктура); один гейт на веху, если задания независимы и правка дёшева (тексты, документация, отдельные страницы). В любом режиме обязательны три гейта: перед заданием, зависящим от результатов группы, перед любым внешним действием и финальный сквозной ревью. Выбранный режим и причина пишутся в реестр прогона — на ретро видно, верным ли был выбор.

## v1.3.0 — 2026-08-10

- Новый скилл **pf-auto** — автопилот: после утверждения спеки оркестратор доводит задачу до done субагентами. Волны заданий по 1–3 тикета; обязательный независимый гейт-ревью после каждого задания; фикс-циклы ≤3 раундов (на третьем — свежий исполнитель на более сильной модели); параллель ≤2 для непересекающихся заданий; стопы безопасности (вопросы только-человеку, противоречия спеке → pf-replan, внешние необратимые действия, пороги окна оркестратора); финальный сквозной ревью на самой сильной модели с одним фикс-заходом. Реестр волн — в HANDOFF (компаньон pf-handoff) или автономно в `.agents/runtime/autopilot-run.md`. Шаблоны промптов — в `skills/pf-auto/references/`.
- pf-tickets упоминает запуск `/pf-auto`; правила §8 (+1 строка): автопилот — только по явной команде человека.
- Проверено синтетическим прогоном: два параллельных исполнителя, оба гейта с доказательствами, заложенный дрейф «спека↔тикет» пойман финальным ревью, один фикс-заход + scoped-реревью чисто, стоп-граница удержана (внешней публикации без человека не было).
- Независимый QA перед релизом (по правилу автора): исправлен счётчик скиллов в заголовке (6, убрано упоминание хуков — они поставляются с pf-handoff), личные пути среды автора в pf-retro/pf-architect помечены как заменяемые, добавлен шаблон реестра для автономных прогонов автопилота.

## v1.2.0 — 2026-08-10

Починка установки на чистых машинах (проблемы воспроизведены в песочнице со свежим $HOME и перепроверены зелёными):

- **`install.sh` теперь по умолчанию ставит копии** — клон после установки можно перемещать или удалять (режим симлинков давал битые ссылки при перемещении клона). `--link` возвращает прежнее поведение симлинков (обновление через `git pull`; клон не перемещать), `--update` обновляет существующие копии.
- **Без мусорных папок**: `~/.codex/skills` и `~/.gemini/skills` затрагиваются только если эти CLI реально есть на машине (`~/.codex` / `~/.gemini` существуют).
- **Анти-перехват**: симлинки, созданные любым другим механизмом управления скиллами, никогда не перезаписываются — пропуск с сообщением (раньше `ln -sfn` молча перенаправлял их на клон).
- README (обе языковые версии): режимы установки задокументированы.
