# Журнал изменений

*[English version](CHANGELOG.md)*

Semver: ломающие изменения (контракт frontmatter task-пакетов, поведенческий контракт скиллов, layout `.agents/`) = major; новые возможности = minor; починки = patch.

## [2.1.0] — 2026-10-22

### Добавлено

- **Где хранить `SOLUTIONS.md`** (журнал решённых проблем). Если `~/.config/pf-handoff/config.json` нет, `install.sh` задаёт тот же вопрос, что и pf-handoff: `1` — ваш репозиторий на GitHub, `2` — локально (по умолчанию; без терминала — молча локально); `PF_HANDOFF_SOLUTIONS=local|github:<url>` отвечает без вопроса. Пишется тот же файл — `solutions_store`, `solutions_repo`, `solutions_path` (файл, в который агент дописывает решения); существующий файл сохраняется, в старый только добавляется `solutions_path`. Для GitHub установщик печатает команду `git clone`, сам не клонирует. Если файл записать нельзя (нет прав на `~/.config`, нет `python3`), установщик печатает `WARN` вместо строки успеха и продолжает.
- **Инструкция удаления** в README (EN и RU): команда, которая снимает только наши записи `Stop` и `SessionStart` из `~/.claude/settings.json` и копии или ссылки скиллов и агентов с нашими именами; что делать с общей папкой `~/.config/pf-handoff/`.
- **`pf-retro`:** новый шаг сбора данных — хранилище SOLUTIONS (у пользователей pf-handoff — `solutions_path`): устаревшие строки — в архив, противоречащие пары без доказательства — в предложение, файл держится в пределах 200 строк.

### Изменено

- **`pf-auto`:** в Claude Code задания остаются субагентами, кроме роли, которую человек назвал на другом агенте («проверь через Antigravity Gemini»), или её запасной — такая роль идёт через `council.sh run`.
- **Обязательного мини-глоссария больше нет.** `pf-architect` объясняет термины в тексте при первом употреблении и к каждому решению человека даёт рекомендацию с причинами; шаблон ретро без раздела «Мини-глоссарий»; `pf-tickets` объясняет формулировку «последний содержательный раздел» служебными разделами после содержания, а не глоссарием.
- **`pf-do`, шаг 5b:** в перечне хуков pf-handoff без собственного скилла больше нет `secrets-guard.sh` (pf-handoff 2.1.0 убирает этот хук).
- Шапка `council.sh` называет оба пути записи (`delegate` и `run --role executor`).
- `tests/run.sh` и комментарии CI: без хвостов удалённых наборов `limits`/`plan-budget`.

### Исправлено

- **Строка `child setpgid` на macOS (`council.sh`, `codex-review.sh`, тестовая библиотека):** запуск помощника или Codex-ревью мог печатать в stderr `child setpgid (N to N): Operation not permitted`. Причина — управление заданиями bash 3.2 (`set -m` в неинтерактивном скрипте): порождённый процесс может проиграть родителю гонку `setpgid` и печатает строку в унаследованный stderr раньше, чем применятся его собственные перенаправления. pf-do запускает процессы под `set -m` в трёх файлах, и строка выходила из каждого: `council.sh` (`with_timeout`), `codex-review.sh` (запуск Codex и отложенный запуск `--async`; однажды строка попала в вывод синхронного ревью) и тестовая библиотека `skills/pf-do/scripts/tests/lib.sh` (`run_with_timeout`), где она попадала в захваченный вывод кейса и под нагрузкой случайно краснила набор. Во всех шести точках запуска ребёнок теперь порождается с заглушённым stderr, а свой stderr пишет туда же, куда раньше (в настоящий stderr или в файл, куда его уже направлял скрипт). Группы процессов, на которые опираются таймауты и `--async`, не изменились; сама гонка управления заданиями осталась, исчезла только лишняя строка. Вызов с закрытым stderr (`2>&-`) по-прежнему запускает помощника. Статический кейс в обвязке тестов `codex-review.sh` теперь проверяет каждую область `set -m` в трёх файлах: новый запуск без этой защиты краснит набор. Проверено на macOS (bash 3.2): обе формы запуска в цикле, 4 копии одновременно — прежняя напечатала строку 10 раз на 24 000 запусков, новая — 0; полный `tests/run.sh`, 4 копии этого кода и 4 копии прежнего кандидата одновременно × 12 раундов — 0 строк `setpgid` за 48 прогонов (гонка редкая: прежний кандидат там тоже дал 0, более ранняя независимая проверка поймала её 2 раза из 48).

## [2.0.0] — 2026-10-12

Major по правилу semver выше: установщик теперь регистрирует хук в вашем `~/.claude/settings.json` (схема установки); у `pf-auto`, `pf-do` и роли исполнителя появился контракт ожидания — ход не может закончиться прозой, пока запущена задача (поведенческие контракты скиллов); у ролей `pf-executor`, `pf-reviewer` и `pf-architect` явно заданы модель, усилие и инструменты (контракты ролей).

### Ломающие изменения

- **Ломающее: `install.sh` регистрирует `hooks/wait-guard.sh` в `~/.claude/settings.json`.** До этого релиза установщик только копировал скиллы и агентов. Теперь каждый запуск ещё и делает upsert хука `Stop` (идемпотентно, ключ — имя файла скрипта; интерпретатор назван явно, поэтому работает под `dash` на Debian/Ubuntu; запись самоотключается, если файл исчез), а при каждом изменении файла сначала копирует прежнее содержимое в `settings.json.bak-pf-workflow` (прошлая копия перезаписывается). Новые флаги: `--sync` (только хуки — скиллы и агентов не трогает) и `--force`. Запись указывает в клон — не перемещайте его или запустите `--sync` из нового места. `CLAUDE_SETTINGS_PATH` переопределяет файл настроек. Чужие хуки (Orca, плагин Codex) не трогаются никогда.
- **Ломающее: установщик оставляет чужую регистрацию того же хука.** Если регистрация `Stop` для `wait-guard.sh` уже указывает на существующий файл вне этого клона (другая копия, чекпоинт мастерской автора), она остаётся как есть, а установщик печатает `KEPT: Stop → <путь> (registered elsewhere; re-run with --force to point it at this clone)`; `bash install.sh --force` переводит её на этот клон (с `--sync` тоже). Регистрация на отсутствующий файл по-прежнему чинится.
- **Ломающее: контракт ожидания.** Ход никогда не заканчивается, пока в реестре есть запущенная задача: ждать можно только блокирующим вызовом, последним вызовом инструмента в ходе (`TaskOutput(block=true)` по каждому запущенному субагенту либо foreground-цикл Bash `until`/`while`; `Monitor` — фоновый поток, а не ожидание). Контракт несут `pf-auto`, `pf-do` (шаги 4a, 4b) и `pf-executor`; в шаблоне реестра появился `session_id`. Его подкрепляет новый хук `Stop` (ниже).
- **Ломающее: контракты ролей.** У `pf-executor` появились `effort: medium` и `skills: [pf-do]` (контракт подгружается вместо «прочитай скилл»); у `pf-reviewer` — `model: opus`, `effort: high`, `disallowedTools: Write, Edit, NotebookEdit` и `skills: [pf-do]`; у `pf-architect` — `model: opus`, `effort: high`. И исполнитель, и ревьюер говорят, что делать, если подгрузка не произошла (сначала прочитать `pf-do/SKILL.md`); ревьюер пишет свои файлы только через heredoc в Bash.

### Изменено

- **`pf-do`:** шаг «поведенческое доказательство про файл правил/скилла, правленный в этой сессии» теперь `5c`; шаг `5b` — гейт evals smoke (ниже). Новые шаги `4a` (долгие запуски: сначала коммит, запуск в фоне, ожидание блокирующим вызовом) и `4b` (диета вывода в автопилоте через `pf-run.sh`). Шаг 5 добавляет правило второго мнения — advisor зовут в трёх фиксированных точках, не больше трёх раз на тикет. Шаг 6 делит пару доказательств: исполнитель отвечает за положительную половину, ревьюер — за враждебную. Шаг 3 просит исполнителя назвать неочевидное допущение от имени человека ДО реализации.
- **`pf-auto`:** строка реестра переписывается сразу после запуска — задача и id субагента (`agentId`, PID или маркер `council.sh`); гейт сравнивает `git diff --name-only BASE..HEAD` с собственным списком файлов тикета (выход за него помечается автоматически); пре-пасс Codex идёт отсоединённо; evals smoke идёт перед каждым вызовом гейта; фикс-цикл считает раунды в колонке реестра `fix_rounds`; поиск роли в `agents/index.yaml` предшествует стандартным ролям; финал L-задачи добавляет слепую приёмку и аудитора согласованности. Пороги оркестратора следуют правилу окна 40/60/75 % из pf-handoff.
- **`pf-tickets`:** критерии приёмки сортируются на `change | invariant | observation` (критерий `change` обязан падать на текущем HEAD до выдачи; для `invariant` инсценируется сбой; `observation` называет проверяемый артефакт). Критерии могут нести поля `cmd` / `expect` / `expect_head` / `cwd` (старые пакеты остаются валидными), которые запускает новый `scripts/criteria-check.sh`; гейт G3 сверяет тикеты со спекой в обе стороны до выдачи. Строка про секреты в шаблоне пакета — константа в каждом пакете.
- **`pf-spec`:** Фаза 0 (поиск цели) для расплывчатой цели, открывается эхо-проверкой — пересказом (`references/goal-discovery.md`). **`pf-replan`:** форма записи дельты в истории изменений спеки (`references/delta-spec.md`). **`pf-retro`:** отчёты ложатся в папку `reports/` проекта-инициативы; три новых раздела ретро — реестр улучшений, который сверяется на каждом ретро, повторения → кандидаты в автоматизацию по правилу трёх и где модели недотягивают (по числу фикс-циклов).
- **`codex-review.sh`:** бюджет времени под потолком Bash агента в 600 с с честными артефактами убитого запуска; отказ определяется по форме вывода, маркер завершения — доказательство того, что ревью состоялось (нет маркера — FAIL, никогда не «чисто»); отсоединённый режим `--async` / `--wait` для диффов, слишком больших для одного прохода, с группами и потолком на весь запуск; отказ Codex называется (`QUOTA`, `LOGIN`, `TIMEOUT`), а не тонет в хвосте stderr. Справка — `skills/pf-do/references/codex-review.md`.
- **Разделы правил (`docs/rules-sections.ru.md`, `.en.md`) переписаны для чужой машины.** До сих пор русский файл генерировался sync-скриптом как почти дословная копия §7–§12 личного свода автора — с путями и правилами его мастерской и правилом про собственную клиентскую среду автора. Теперь оба файла — собственные файлы репозитория: тот же процесс (масштаб S/M/L, task-пакеты, журнал, ревью, приёмка внешних скиллов) без путей, инструментов и имён среды автора; протокол заявок — только если вы ведёте общий файл заявок. Sync-скрипт их больше не трогает. Русский и английский говорят одно и то же.
- **Тесты:** `tests/run.sh` теперь ещё гоняет группы wait-guard, council, pf-run и сканера секретов; `actionlint` необязателен.

### Укрепление перед релизом (независимый враждебный QA, 2026-10-11)

- **Никаких частных данных в поставке.** Имена проектов и клиентов автора убраны из комментариев поставляемых сканера, хука и тестов; `sync-from-tools.sh` останавливается (код 3, называет `файл:строку`, само слово не печатает), если в дереве нашлось слово из частного стоп-листа автора, а `tests/run.sh` делает ту же проверку, когда список есть (он не поставляется; без него проверка пропускается).
- **`hooks/wait-guard.sh` читает файлы реестра безопасно.** Только обычные файлы — не симлинки, не устройства, не FIFO, не каталоги — и не больше первых 1 МБ / 5000 строк каждого, до любого разбора (живые реестры доходят до ~500 строк). Симлинк на `/dev/zero`, подложенный в репозиторий, раньше раздувал хук до гигабайт на каждом Stop; теперь он пропускается за миллисекунды. Строки реестра дальше этого предела не видны (хук тогда уступает).
- **`install.sh`:** путь клона с апострофом (`Mike's tools`) теперь даёт рабочую команду хука (кавычка экранируется; раньше Stop-хук не разбирался и возвращал 2 на каждом ходе); внутри группы хуков заменяется только НАШ объект — чужой хук той же группы и её `matcher` остаются (и при `--sync`); копия `settings.json.bak-pf-workflow` получает права оригинала (файл 0600 больше не оставляет копию 0644).
- **У `session_id` есть источник.** Новый хук `SessionStart` `hooks/pf-session-id.sh`, `install.sh` регистрирует его так же, как Stop-хук (upsert/KEPT): он печатает `Сессия: <8 знаков> — это значение поля session_id в HANDOFF/реестре`, а шаг 2 `pf-auto` и шаблон реестра велят агенту переписать эти 8 знаков. Молчит, если ту же строку уже печатает хук старта pf-handoff, и в агентах, запущенных `council.sh`.
- **`council.sh run`:** всё, что он пишет в тикет, — финальное сообщение агента и строки состояния, которые при сбое цитируют последнюю строку вывода CLI, — сначала проходит тот же секрет-скан: при находке в тикет идёт только строка «ответ не записан: секрет-скан нашёл совпадение», результат FAIL, ничего не коммитится (нет сканера — тот же FAIL с подсказкой установить `gitleaks`); свои файлы (`.claude/worktrees/`, `.agents/runtime/council-ledger.tsv`, `.agents/runtime/council/`) он прописывает в локальный `.git/info/exclude` репозитория, и `git status` остаётся чистым (git-сторож следит за этим файлом, незаметно агенту его не поменять); каждый дочерний CLI получает `PF_COUNCIL_RUN=1`, поэтому хуки старта сессии молчат у исполнителя и ревьюера со свежим контекстом.

### Укрепление перед релизом (повторный враждебный QA, 2026-10-12)

- **`council.sh delegate --audit`:** запись, которую он дописывает в `<проект>/.agents/journal/<дата>.md` — отслеживаемый файл, — сначала проходит тот же секрет-скан, что текст тикета у `run`. Её строка «Итог» цитирует состояние помощника, а при ошибке CLI это последняя строка его вывода; при находке (или если скан не смог запуститься) в журнал идёт только нейтральная запись без цитаты, и прогон — FAIL.
- **Вывод `council.sh` при ошибке не цитирует текст CLI.** Строка `FAIL: <помощник> error (…)` называет код возврата и файл сырого вывода в `.agents/runtime/council/` (вне git) — `подробности: <путь>` — вместо последней строки вывода CLI: её пишет агент, и в ней может оказаться ключ.
- **`council.sh` называет старый gitleaks.** Секрет-скан вызывает `gitleaks git` — эта команда есть в gitleaks с 8.19; apt в Ubuntu 24.04 даёт 8.16. Если скан не смог запуститься, сообщение теперь говорит «could not be secret-scanned», а не «failed», и называет исправление: gitleaks ≥ 8.19 — macOS `brew install gitleaks`, Ubuntu/Debian — бинарник с GitHub Releases; gitleaks без `gitleaks git` назван слишком старым. README: требование и шаг проверки агента (`gitleaks git --help`).
- **Хук `SessionStart` называется `hooks/pf-session-id.sh`** (до релиза — без префикса `pf-`): установщик узнаёт свои хуки по имени файла, а общее имя совпадало с логгерами сессий других инструментов. Миграция не нужна — старое имя не выходило ни в одном релизе.
- **`council.sh` и `.git/info/exclude`:** последняя строка пользователя без перевода строки больше не склеивается с нашим первым шаблоном (`*.log/.claude/worktrees/`); вызов, отклонённый из-за аргументов, туда ничего не пишет.
- **Тихий режим дочерних CLI — с pf-handoff ≥ 2.0.0.** `PF_COUNCIL_RUN=1` глушит хук старта pf-handoff только начиная с pf-handoff 2.0.0; со старым pf-handoff ребёнок `council.sh` всё ещё получает подсказку прочитать HANDOFF и продолжить — обновите оба (README, «Обновление»).

### Добавлено

- **`hooks/wait-guard.sh` — хук Claude Code `Stop`.** Закрывает зависание «пассивного ожидания» (три автопилота простояли часами после хода, закончившегося «Жду»): когда реестр ЭТОЙ сессии (активный HANDOFF или `autopilot-run.md`, у которого `session_id` совпал со stdin хука) всё ещё содержит запущенную задачу, а ход заканчивается прозой, хук блокирует остановку одной строкой-причиной. Он живёт рядом с другими хуками `Stop` (Orca, stop-review-gate плагина Codex): Claude Code запускает каждый зарегистрированный хук `Stop` в порядке настроек, каждый решает сам; наш читает только stdin и транскрипт, ничего не пишет и уступает при любом сомнении.
- **`skills/pf-do/scripts/council.sh`** — запускает исполнителя или ревьюера со свежим контекстом отдельным процессом CLI там, где у платформы нет инструмента субагентов, и спрашивает CLI помощников (`agy`, `grok`, `codex`) о втором мнении только на чтение: `check`, `consult`, `review`, `parallel`, `ask`, `run` и `delegate` (помощник пишет код в своём worktree по закрытому контракту; `delegate --audit` — для аудита). Бэкенды пробуются в порядке `.agents/council.json`; помощник, у которого кончилась квота, который не залогинен или завис, пропускается к следующему. `run` коммитит работу агента только после секрет-скана — **`gitleaks` должен быть в PATH**. Сканер ищется так: `PF_SECRET_SCAN`, затем checkout канона, затем копия рядом со скриптом (`skills/pf-do/scripts/secret-scan/`) — поэтому машина без мастерской автора работает.
- **`skills/pf-do/scripts/pf-run.sh`** — запускает команду с длинным выводом в файл и печатает голову, хвост, строки, похожие на сбой, и строку `saved:`. **`skills/pf-do/references/second-opinion.md`** — когда звать advisor, совет и режим делегирования.
- **`pf-auto` без инструмента субагентов** (Codex, Antigravity, Grok CLI): тот же цикл с `council.sh` в роли запускателя.
- **`agents/index.yaml`** — пустой реестр поиска ролей, который `pf-auto` проверяет до стандартных ролей; `sync-from-tools.sh` его переносит.

## v1.2.0 — 2026-08-10

Починка установки на чистых машинах (проблемы воспроизведены в песочнице со свежим $HOME и перепроверены зелёными):

- **`install.sh` теперь по умолчанию ставит копии** — клон после установки можно перемещать или удалять (режим симлинков давал битые ссылки при перемещении клона). `--link` возвращает прежнее поведение симлинков (обновление через `git pull`; клон не перемещать), `--update` обновляет существующие копии.
- **Без мусорных папок**: `~/.codex/skills` и `~/.gemini/skills` затрагиваются только если эти CLI реально есть на машине (`~/.codex` / `~/.gemini` существуют).
- **Анти-перехват**: симлинки, созданные любым другим механизмом управления скиллами, никогда не перезаписываются — пропуск с сообщением (раньше `ln -sfn` молча перенаправлял их на клон).
- README (обе языковые версии): режимы установки задокументированы.
