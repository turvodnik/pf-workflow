# Changelog

*[Русская версия](CHANGELOG.ru.md)*

Semver: breaking changes (task-packet frontmatter contract, skill behavior contracts, `.agents/` runtime layout) = major; new features = minor; fixes = patch.

## [2.1.1] — 2026-10-23

Fixes from an independent full review (not a diff review) of 2.1.0; the defects below were already in 2.0.0.

### Fixed

- **`session_id` is stored in full and compared exactly** (`hooks/pf-session-id.sh`, `hooks/wait-guard.sh`, `pf-auto` step 2, the registry template). Two sessions whose ids share the first 8 characters accepted each other's registry, because the hook printed 8 characters and the guard took any prefix as a match. The start line now prints the full id (8–128 characters), and "own" means exact equality. Compatibility: a registry written before 2.1.1 with an 8-character value is still guarded, unless another registry in the project carries an id with the same prefix (a full one or another short one) — an ambiguous prefix belongs to nobody. The guard looks for that conflict among active HANDOFF files and `autopilot-run.md` (pf-handoff's start hook — among HANDOFF files only). A 9+ character prefix is no longer a match. A lone legacy value still cannot tell apart two sessions that share its prefix — rewrite it with the full id.
- **A timed-out wait no longer lets the turn end** (`hooks/wait-guard.sh`). The guard looked only at the last call (`TaskOutput(block=true)`, a Bash wait loop) and not at its result. Now a wait that came back with `retrieval_status` timeout / `status` running (read from the result's service fields, not from the job's output), or a failed Bash wait with `Command timed out after` / `FAIL: wait timeout`, blocks the stop once more. The deliberate stop stays open: mark the job in the registry with a status other than «запущен»; the one-nudge-per-turn limit (`stop_hook_active`) still prevents an endless wait.
- **A broken acceptance probe is no longer "red on HEAD"** (`pf-tickets/scripts/criteria-check.sh`). `printf (` gave `STDERR WARN`, `OK (red on HEAD)` and rc 0. Now a command that does not parse (`bash -n`, a nested shell's "syntax error", a Python `SyntaxError`/`IndentationError`, a grep regex error recognised by the BSD/GNU/ugrep wording of its message — only the listed wordings, e.g. `*`, `[b-a]`, `a{2,1}`, an unbalanced bracket; not "any exit code 2", because a program under test may legitimately exit 2 on a flag it does not know yet; a probe error with a wording not on the list can still pass as `OK (red on HEAD)` — for such a probe declare `expect_head_rc:`), or fails with a missing/unreadable file in stderr, is a `PROBE-ERROR` with exit 2; a Python `Traceback`/`ModuleNotFoundError` stays a legitimate red. A legitimate negative probe (non-zero rc without such stderr, e.g. `grep -c` finding 0) is accepted as before; a red state that IS such an error (the work creates the file; the program under test reports a syntax error) is declared with the new optional field `expect_head_rc:`, which is also checked.
- **`install.sh` fails when the hooks are not registered.** With a broken `~/.claude/settings.json` — or a hook skipped because it is not executable or declares no `# hook-event:` — the default install printed the error, then `Done` with rc 0 (`--sync` already failed on a broken file). Now both fail with rc 1 (the other hooks are still registered); the settings file stays unchanged, and the default install prints `INCOMPLETE` with the `--sync` command to re-run.
- **`pf-do` step 3:** a HANDOFF checkpoint only for a standalone executor with no orchestrator; under an orchestrator the HANDOFF is the orchestrator's — the executor neither creates nor rewrites it (same rule as pf-handoff 2.1.1).
- **`pf-auto` step 3:** BASE for the review diff is recorded BEFORE the executor starts (for a worktree — its start commit), so an executor's immediate first commit is inside `BASE..HEAD`.

## [2.1.0] — 2026-10-22

### Added

- **Where to keep `SOLUTIONS.md`** (the log of solved problems). If `~/.config/pf-handoff/config.json` does not exist, `install.sh` asks the same question as pf-handoff: `1` — your own GitHub repository, `2` — locally (default; silently local with no terminal); `PF_HANDOFF_SOLUTIONS=local|github:<url>` answers without a question. It writes the same file — `solutions_store`, `solutions_repo`, `solutions_path` (the file the agent appends to); an existing file is kept, an older one only gets `solutions_path` added. For GitHub the installer prints the `git clone` command; it does not clone. If the file cannot be written (no permission on `~/.config`, no `python3`), the installer prints a `WARN` instead of a success line and goes on.
- **Uninstall instructions** in the README (EN and RU): a command that removes only our `Stop` and `SessionStart` entries from `~/.claude/settings.json` and the skill and agent copies or links that carry our names; what to do with the shared `~/.config/pf-handoff/`.
- **`pf-retro`:** a new data step — the SOLUTIONS store (`solutions_path` for pf-handoff users): outdated rows go to the archive, contradicting pairs without proof become a proposal, the file stays within 200 lines.

### Changed

- **`pf-auto`:** in Claude Code, jobs stay subagents except a role the human named on another agent («проверь через Antigravity Gemini») or its fallback — that role runs through `council.sh run`.
- **No mandatory mini-glossary.** `pf-architect` explains terms in the text at first use and gives a recommendation with reasons for every decision of the human; the retro template drops the «Мини-глоссарий» section; `pf-tickets` explains the «last substantive section» wording by service sections that follow the content, not by the glossary.
- **`pf-do`, step 5b:** the list of pf-handoff hooks without an owning skill no longer names `secrets-guard.sh` (pf-handoff 2.1.0 removes that hook).
- `council.sh` header names both write paths (`delegate` and `run --role executor`).
- `tests/run.sh` and CI comments: no leftovers of the removed `limits`/`plan-budget` harnesses.

### Fixed

- **`child setpgid` line on macOS (`council.sh`, `codex-review.sh`, test library):** a helper run or a Codex review could print `child setpgid (N to N): Operation not permitted` to stderr. Cause: bash 3.2 job control (`set -m` in a non-interactive script) — the forked child may lose the `setpgid` race with its parent and prints the line with the stderr it inherited, before its own redirections apply. pf-do starts processes under `set -m` in three files, and the line came out of each: `council.sh` (`with_timeout`), `codex-review.sh` (the Codex run and the detached `--async` launch; once the line landed in the output of a synchronous review) and the test library `skills/pf-do/scripts/tests/lib.sh` (`run_with_timeout`), where it landed in the captured output of a case and turned the suite red at random under load. In all six fork points the child is now forked with stderr muted and still writes its own stderr where it did before (the real stderr, or the file the script already redirected it to). The process groups the timeouts and `--async` rely on are unchanged; the job-control race itself remains, only the stray line is gone. A caller with stderr closed (`2>&-`) still gets the helper run. A static case in the `codex-review.sh` test harness now checks every `set -m` region of the three files, so a new fork without the cure turns the suite red. Checked on macOS (bash 3.2): the two fork forms in a loop, 4 copies at once — the old form printed the line 10 times in 24,000 forks, the new one 0; the full `tests/run.sh`, 4 copies of this code and 4 of the previous candidate at once × 12 rounds — 0 `setpgid` lines in 48 runs (the race is rare: the previous candidate gave 0 there too, an earlier independent check caught it 2 times in 48).

## [2.0.0] — 2026-10-12

Major by the semver rule above: the installer now registers a hook in your `~/.claude/settings.json` (the install scheme); `pf-auto`, `pf-do` and the executor role gain a waiting contract — a turn may not end in prose while a job is running (skill behavior contracts); the `pf-executor`, `pf-reviewer` and `pf-architect` roles get explicit model, effort and tool settings (role contracts).

### Breaking

- **Breaking: `install.sh` registers `hooks/wait-guard.sh` in `~/.claude/settings.json`.** Before this release the installer only copied skills and agents. Now every run also upserts the `Stop` hook (idempotent, keyed by the script file name; the interpreter is named explicitly so it works under `dash` on Debian/Ubuntu; the entry self-disables if the file is gone), copying the previous contents to `settings.json.bak-pf-workflow` each time it changes the file (the earlier copy is overwritten). New flags: `--sync` (hooks only — skills and agents untouched) and `--force`. The entry points into the clone — do not move it, or re-run `--sync` from the new place. `CLAUDE_SETTINGS_PATH` overrides the settings file. Other tools' hooks (Orca, the Codex plugin) are never touched.
- **Breaking: the installer keeps someone else's registration of the same hook.** If the `Stop` registration of `wait-guard.sh` already points at an existing file outside this clone (another copy, a checkout of the author's workshop), it is left as it is, with `KEPT: Stop → <path> (registered elsewhere; re-run with --force to point it at this clone)`; `bash install.sh --force` points it at this clone (with `--sync` too). A registration on a missing file is repaired as before.
- **Breaking: the waiting contract.** A turn never ends while the registry has a running job: waiting is a blocking call only, as the last tool call of the turn (`TaskOutput(block=true)` per running subagent, or a foreground Bash `until`/`while` loop; `Monitor` is a background stream, not a wait). `pf-auto`, `pf-do` (steps 4a, 4b) and `pf-executor` carry it; the registry template gets a `session_id`. Backed by the new `Stop` hook (below).
- **Breaking: role contracts.** `pf-executor` gets `effort: medium` and `skills: [pf-do]` (preloads the contract instead of "read the skill"); `pf-reviewer` gets `model: opus`, `effort: high`, `disallowedTools: Write, Edit, NotebookEdit` and `skills: [pf-do]`; `pf-architect` gets `model: opus`, `effort: high`. Both executor and reviewer say what to do when the preload did not happen (Read `pf-do/SKILL.md` first); the reviewer writes its own files only through Bash heredocs.

### Changed

- **`pf-do`:** the step "behavioral proof about a rules/skill file edited this session" is now `5c`; step `5b` is the evals smoke gate (below). New steps `4a` (long runs: commit first, run in the background, wait by a blocking call) and `4b` (output diet in the autopilot via `pf-run.sh`). Step 5 adds the second-opinion rule — the advisor is called at three fixed points, at most three times per ticket. Step 6 splits the proof pair: the executor owns the positive half, the reviewer the hostile half. Step 3 asks the executor to name a non-obvious assumption made on the human's behalf BEFORE implementing it.
- **`pf-auto`:** the registry row is rewritten right after a launch with the job and the subagent id (`agentId`, a PID or a `council.sh` marker); the gate compares `git diff --name-only BASE..HEAD` with the ticket's own file list (scope creep is flagged automatically); the Codex pre-pass runs detached; the evals smoke runs before every gate invocation; the fix cycle counts rounds in a `fix_rounds` column; a role lookup in `agents/index.yaml` precedes the standard roles; the final step on an L task adds a blind-acceptance review and a consistency auditor. Orchestrator thresholds follow the 40/60/75 % window rule of pf-handoff.
- **`pf-tickets`:** acceptance criteria are sorted into `change | invariant | observation` (a `change` criterion must fail on the current HEAD before hand-out; an `invariant` gets a staged failure; an `observation` names the artifact inspected). Criteria may carry `cmd` / `expect` / `expect_head` / `cwd` fields (old packets stay valid), run by the new `scripts/criteria-check.sh`; gate G3 reconciles tickets with the spec in both directions before hand-out. The packet template's secrets line is constant in every packet.
- **`pf-spec`:** Phase 0 (goal discovery) for a fuzzy goal, opened by an echo-check paraphrase (`references/goal-discovery.md`). **`pf-replan`:** a delta record form in the spec's change history (`references/delta-spec.md`). **`pf-retro`:** reports go to the initiative project's `reports/` folder; three new retro sections — an improvement ledger reconciled every retro, repetition → automation candidates by the rule of three, and where models underperform (fed by fix-cycle counts).
- **`codex-review.sh`:** a time budget under the 600 s agent Bash ceiling with honest artifacts for a killed run; a refusal by the shape of the output, a completion marker as the proof that a review happened (no marker means FAIL, never "clean"); a detached `--async` / `--wait` mode for diffs too large for one pass, with chunked groups and a whole-run cap; a refusal by Codex is named (`QUOTA`, `LOGIN`, `TIMEOUT`) instead of buried in a stderr tail. The reference is `skills/pf-do/references/codex-review.md`.
- **Rules sections (`docs/rules-sections.en.md`, `.ru.md`) rewritten for someone else's machine.** Until now the Russian file was generated by the sync script as a near-verbatim copy of §7–§12 of the author's personal rule set — with paths and rules of the author's workshop and a rule about one of the author's own client setups. Both files are now this repository's own: the same process (S/M/L scale, task packets, journal, review, acceptance of external skills) with no paths, tools or names of the author's environment; the claims protocol applies only when you keep a shared claims file. The sync script no longer touches them. English and Russian say the same thing.
- **Tests:** `tests/run.sh` also runs the wait-guard, council, pf-run and secret-scanner groups; `actionlint` is optional.

### Hardening before release (independent hostile QA, 2026-10-11)

- **No private data in the package.** Names of the author's projects and clients are gone from comments of the shipped scanner, hook and tests; `sync-from-tools.sh` stops (exit 3, names `file:line`, never the word) when a word from the author's private stop-list turns up in the tree, and `tests/run.sh` runs the same check when the list is present (it is not shipped; without it the check is skipped).
- **`hooks/wait-guard.sh` reads registry files safely.** Only regular files — no symlinks, devices, FIFOs or directories — and at most the first 1 MB / 5000 lines of each, before any parsing (live registries reach ~500 lines). A symlink to `/dev/zero` planted in a repository used to grow the hook to gigabytes on every Stop; now it is skipped in milliseconds. Registry rows past that limit are not seen (the hook then yields).
- **`install.sh`:** a clone path with an apostrophe (`Mike's tools`) now gives a working hook command (the quote is escaped; before, the Stop hook failed to parse and returned 2 on every turn); only OUR hook object is replaced inside a hook group — a foreign hook in the same group and the group's `matcher` stay (also with `--sync`); the `settings.json.bak-pf-workflow` copy gets the mode of the original (a 0600 file no longer leaves a 0644 copy).
- **`session_id` has a source.** New `SessionStart` hook `hooks/pf-session-id.sh`, registered by `install.sh` like the Stop hook (upsert/KEPT): it prints `Сессия: <8 characters> — это значение поля session_id в HANDOFF/реестре`, and `pf-auto` step 2 and the registry template tell the agent to copy those 8 characters. Silent when pf-handoff's own start hook already prints the line, and in agents started by `council.sh`.
- **`council.sh run`:** everything it writes into the ticket — the agent's final message and the state lines, which quote the CLI's last output line on a failure — passes the same secret scan first: on a finding the ticket gets only `ответ не записан: секрет-скан нашёл совпадение`, the run is a FAIL and nothing is committed (no scanner → the same FAIL with a hint to install `gitleaks`); its own files (`.claude/worktrees/`, `.agents/runtime/council-ledger.tsv`, `.agents/runtime/council/`) go to the repository's local `.git/info/exclude`, so `git status` stays clean (the git guard watches that file, so an agent cannot change it unnoticed); every child CLI gets `PF_COUNCIL_RUN=1`, so session-start hooks stay silent in a fresh-context executor or reviewer.

### Hardening before release (repeat hostile QA, 2026-10-12)

- **`council.sh delegate --audit`:** the journal entry it appends to `<project>/.agents/journal/<date>.md` — a tracked file — passes the same secret scan as the ticket text of `run` first. Its "Итог" line quotes the helper's state, which on a CLI failure is the CLI's last output line; on a finding (or when the scan cannot run) the journal gets only a neutral entry with no quote, and the run is a FAIL.
- **`council.sh` output quotes no CLI text on an error.** A `FAIL: <helper> error (…)` line names the exit code and the raw-output file under `.agents/runtime/council/` (outside git) — `подробности: <path>` — instead of the CLI's last output line, which the agent controls and which could carry a key.
- **`council.sh` names an old gitleaks.** The secret scan runs `gitleaks git`, a command gitleaks has since 8.19; Ubuntu 24.04's apt ships 8.16. When the scan cannot run, the message now says "could not be secret-scanned", not "failed", and names the fix: gitleaks ≥ 8.19 — macOS `brew install gitleaks`, Ubuntu/Debian the binary from GitHub Releases; a gitleaks without `gitleaks git` is called too old. README: requirement and the agent's check step (`gitleaks git --help`).
- **The `SessionStart` hook is named `hooks/pf-session-id.sh`** (before this release the name had no `pf-` prefix): the installer recognises its hooks by file name, and a common name matched other tools' session loggers. No migration — the old name was never in a release.
- **`council.sh` and `.git/info/exclude`:** a user's last line without a newline is no longer glued to our first pattern (`*.log/.claude/worktrees/`); a call refused for its arguments writes nothing there.
- **Child CLIs need pf-handoff ≥ 2.0.0 to stay quiet.** `PF_COUNCIL_RUN=1` silences pf-handoff's start hook only from pf-handoff 2.0.0 on; with an older pf-handoff a child of `council.sh` still gets the hint to read the HANDOFF and continue — update both (README, Update).

### Added

- **`hooks/wait-guard.sh` — a Claude Code `Stop` hook.** Closes the "passive wait" stall (three autopilots stood for hours after a turn ending with "Жду"): when the registry of THIS session (an active HANDOFF or `autopilot-run.md` whose `session_id` matches the hook's stdin) still has a running job and the turn ends in prose, it blocks the stop with one reason line. It lives next to other Stop hooks (Orca, the Codex plugin's stop-review-gate): Claude Code runs every registered Stop hook in settings order, each decides alone; ours reads only stdin and the transcript, writes nothing, and yields on any doubt.
- **`skills/pf-do/scripts/council.sh`** — runs a fresh-context executor or reviewer as a separate CLI process where the platform has no subagent tool, and asks the helper CLIs (`agy`, `grok`, `codex`) for a read-only second opinion: `check`, `consult`, `review`, `parallel`, `ask`, `run`, and `delegate` (a helper writes code in its own worktree under a gated contract; `delegate --audit` for an audit). Backends are tried in the order of `.agents/council.json`; a helper that is out of quota, logged out or timed out is skipped to the next one. `run` commits the agent's work only after a secret scan — **`gitleaks` must be in PATH**. It finds the scanner as `PF_SECRET_SCAN`, then the canon checkout, then the copy shipped next to it (`skills/pf-do/scripts/secret-scan/`) — so a machine without the author's workshop works.
- **`skills/pf-do/scripts/pf-run.sh`** — runs a command with a long output into a file and prints a head, a tail, failure-looking lines and a `saved:` line. **`skills/pf-do/references/second-opinion.md`** — when to call the advisor, the council and the delegate mode.
- **`pf-auto` without a subagent tool** (Codex, Antigravity, Grok CLI): the same cycle with `council.sh` as the launcher.
- **`agents/index.yaml`** — an empty role-lookup registry that `pf-auto` checks before falling back to the standard roles; `sync-from-tools.sh` carries it.
- **`evals/`: 5 contract cases** for `claude plugin eval` (`reviewer-distrusts-result`, `executor-writes-evidence`, `autopilot-never-ends-with-wait`, `pf-do-gates-rule-file-edit`, `qa-hostile-ignores-author-tests`), each anchored to an incident or a rule, with fixtures from a `scaffold.sh` and free graders. `evals/README.md` records the first full run (opus, judge sonnet, threshold 0.8, two arms): `partial: cost_ceiling` at $20.16 after 23 of 30 sessions, so `reviewer-distrusts-result` did not start. `pf-do` step `5b` runs `evals.sh smoke` when a diff touches a role, skill or hook file. `.claude-plugin/plugin.json` is a manifest for `claude plugin validate`/`eval` only; it declares no `hooks`, so `install.sh` stays the install path.
- **README:** a "For your AI agent" section (exact install, check, update and first-phrase steps an agent can follow as written), an "Update" block (`cd <clone> && git pull && bash install.sh --update`) and the `KEPT` / `--force` explanation.

## v1.8.0 — 2026-08-13

Canon re-synced: a stricter dependency gate, `codex-review.sh` hardened further, plus a test suite that watches its own back.

- **Dependency gate is now done-only.** `depends_on` used to clear on a dependency in `done` *or* `review`; `review` alone no longer counts — `pf-auto` may still start a job on a `review` dependency, but only as an explicit, reasoned exception recorded in the wave registry, never silently. Minor, not major: this tightens an existing safety contract (closes a gap where a ticket could start on an unreviewed dependency) the same way v1.5.0's blocked-work-must-be-committed rule did — it does not rename or remove anything a caller depends on.
- **`pf-auto`'s Codex pre-pass no longer hangs on a literal placeholder.** The resolver line in `pf-auto/SKILL.md` used to run `bash "$SC" --base <BASE> --deep` verbatim — bash reads the unquoted `<BASE>` as `< BASE`, a stdin redirect from a file that does not exist (F-15, originally fixed in canon by T-014; this repo's own copy had drifted behind it until this sync). It now reads `PF_AUTO_BASE` from the environment and prints an explicit "no BASE recorded" note when it is unset, instead of failing on the placeholder text itself. `tests/base-exec.sh` (below) is the regression guard for exactly this line.
- **`codex-review.sh` hardened again.** Six findings on top of v1.7.0's eight are closed here: five in the review logic itself — consent is fail-closed on every unreadable, malformed or ambiguous state of the consent file, not only a recorded `false`; `--out` now refuses a FIFO, a dangling symlink and a directory (previously just an existing file), with `noclobber` closing the check-then-write race between the refusal check and the write itself; a Codex run that exits 0 with an auth-failure/rate-limit/traceback-shaped message now reads as "not reviewed", not "0 findings"; a `--base`/`--commit` ref is resolved to a full hex commit SHA before it reaches a prompt or `argv`, so shell metacharacters legal in a git ref name (`;`, `` ` ``, `$()`) can no longer leak through; the timeout watchdog no longer races its own `wait` — bash 3.2 returns from `wait` on a disowned PID immediately, without actually waiting, which used to let a SIGTERM-resistant descendant survive past the deadline — plus a sixth, portability rather than logic: its own two `mktemp` calls move off the BSD-only `-t <prefix>` form that GNU coreutils (`ubuntu-latest`) rejects outright, the same fix as in the test suite below.
- **`--out` no longer clobbers a different file than the one it just checked.** A *relative* `--out` was never absolutized: the F-05 existence guard and the `noclobber` test-write ran in the caller's own working directory, but the actual report write ran later, after this script's internal `cd` to the repo root — so a relative path could resolve to two different files, with the guard protecting one while a plain `>` truncated the other, behind a reported `OK`. Found in a subsequent independent review pass, not by the authored regression test itself: that test always ran from the repo root with an absolute `--out`, the one blind spot this bug lived in. `OUT` is now absolutized immediately after it is decided, before any guard check and before the `cd`; two regression cases were added to `skills/pf-do/scripts/tests/run.sh` to cover it directly (59 → 61 total cases).
- **Strict YAML frontmatter**: `pf-retro`'s `description` is now quoted — unquoted, the `cadence: 2 weeks → a month` aside inside it reads as a nested mapping key under a strict YAML parser. The other eight skill/agent descriptions don't need it: none of them contain that colon-space shape.
- **New: `bash tests/run.sh` + GitHub Actions CI.** One command runs `bash -n` and ShellCheck on every script, validates the workflow YAML, re-runs the `codex-review.sh` safety harness (T-008, 61 cases) and a full-canon YAML-strict frontmatter scan (T-009), checks that every `SKILL.md` resolver line is actually executable (`tests/base-exec.sh`), and two negative controls (a mutated file must turn its own check red). Portable `mktemp` throughout (a BSD-only `-t <prefix>` form silently no-ops the negative controls on `ubuntu-latest`'s GNU coreutils — found and fixed before this shipped, not after). README (both languages) gets the CI badge and a one-line "how to run it locally".
- **The new test suite hardened again, same day (fix round on this release, before tagging):** the workflow-YAML check now SKIPs, not FAILs, when `python3` has no PyYAML module — it used to blame a valid file for a missing third-party module on the exact stock configuration (`python3` present, PyYAML absent) that ships on `ubuntu-latest` and on macOS's Command Line Tools; each of the three sub-harnesses (`codex-review`, `yaml-strict`, `base-exec`) now has its own exit code checked, so one that aborts mid-setup (missing `jq`, no YAML-capable interpreter) can no longer read as "fully green" through the `known-failures-T017.txt` bookkeeping, which only tracks named cases, not "did this even run"; the no-network `grep`'s self-exclusion is anchored to this file's own absolute path instead of matching any file named `run.sh`, so a real `curl`/`wget` added to the transplanted `codex-review.sh` test harness could no longer hide behind it; and — in the same fix round — the F-11 check (the watchdog kills Codex's whole process group) no longer counts a zombie process (defunct — already dead, not yet reaped by PID 1) as alive: `kill -0` sees the zombie entry and, under a non-reaping PID 1 (a bare container with no init-reaper), gave a false red even though the watchdog itself worked correctly — the check now inspects process state and treats a zombie as dead. The shipping `codex-review.sh` is untouched: the grandchild reparents to PID 1, not to the watchdog, so the test is fixed, not the product.
- `pf-spec`'s `spec-template.md` no longer hardcodes an owner name in the template body.

Verified: `bash tests/run.sh` — 11/11 GREEN, and — unlike every run before this release — the three re-synced sub-harnesses (codex-review 61/61, yaml-strict 9/9, base-exec 2/2) are green on their own merits, not merely matched against `tests/known-failures-T017.txt`, which is now empty for the first time since it was introduced.

## v1.7.1 — 2026-08-12

Discretionary findings of the v1.7.0 independent QA, all closed:

- `--yes` no longer overrides a recorded refusal: `{"enabled": false}` is a decision the human made (pf-spec writes it precisely so nobody asks again), not a missing answer. A missing file and an unreadable file are now distinguished too.
- The report no longer dirties the working tree — the report directory carries its own `.gitignore`, so pf-auto's "the tree must be clean between waves" still holds in someone else's project.
- Two runs in the same minute no longer overwrite each other's report (seconds in the stamp).
- `--help` printed the first line of code; the script path is resolved across every surface the installer writes to (`~/.claude`, `~/.codex`, `~/.gemini`) instead of being pinned to `~/.claude`, so a machine without it gets a silent skip rather than a bash error; the last Russian comments in an otherwise English file are translated.
- The watchdog now signals Codex's whole process group (`set -m`), so children no longer outlive a timeout.

## v1.7.0 — 2026-08-12

Optional Codex second opinion, wired into the pipeline:

- **New: `skills/pf-do/scripts/codex-review.sh`** — a read-only review of the current diff by the local Codex CLI. The full report goes to a file (`workspace/runs/codex-review/`), only a ~6-line digest reaches the agent's context, so a review costs minutes of wall-clock and almost no window.
- **Nothing is required.** Four silent gates, each exiting 0: no `codex` in PATH → no project consent (`.agents/codex-review.json`) → not a git repo or an empty diff → a diff with only prose and lockfiles. Without Codex installed the pipeline behaves exactly as before — that is the point, not a fallback.
- **Hooks:** `pf-do` step 5a (before `status: review`), `pf-auto` — a pre-pass before a milestone gate (`--deep`, never replacing the reviewer subagent), `pf-spec` step 4a — the single consent question, asked while the spec is written and only when `codex` exists on the machine, `pf-handoff` step 2a (companion tool) — on closing a session that still holds uncommitted code.
- **`pf-do/references/codex-review.md`** — the runbook: the two review modes and why a focused pass cannot use the native reviewer, the model policy (`gpt-5.6-luna`/`max` fast lane, `gpt-5.6-sol`/`xhigh` deep lane, `ultra` banned), and the traps: `codex exec review` always exits 0, an empty report means the run died, `codex exec` hangs forever without `</dev/null`.
- **Why a reviewer that does not replace §6:** Codex frames the native review itself, so the caller's blind spot stays out of the prompt — but it runs on the same machine against the same repository. It is the cheap half of the check, not the independent audit.

Eight defects of the tool itself were found and fixed before release, six of them by Codex reviewing this very script: an argument without a value spun the parser forever; `--deep` did not override a fast-lane project config; configs, CI workflows and schemas were filtered out as "docs"; untracked files were invisible in focused mode; an unwritable `--out` reported "OK, 0 findings"; the watchdog sent a single SIGTERM with no follow-up kill; `-s` did not distinguish a directory from a file (a second false-clean path); and the watchdog killed a subshell wrapper instead of Codex itself.

Independent QA before release added two more, both fixed: the watchdog held the script's stdout, so a caller reading the output through command substitution hung until the timeout budget expired *after* a successful review (and stray `sleep` processes piled up); and file names containing spaces or non-ASCII come back quoted from git, so the docs-only gate failed to recognise them — path lists are read with `-z` now. Also fixed: the native mode now pins `sandbox_mode="read-only"` it already claimed in the report; consent is no longer ignored with a wrong reason on a machine without both `jq` and `python3`; `"True"` in the consent file means the same everywhere; an unknown flag reports on stdout, where the caller is told to read.

## v1.5.0 — 2026-08-11

Findings from a second isolated test run (edge cases, not the happy path):

- **pf-do**: work done before a blocker must now be committed too (the commit-message literal is Russian: `T-###: blocked — сохраняю сделанное, <причина>`, "saving what was done") — an uncommitted tail breaks the next gate's diff and is lost when the session changes; evidence in "Result" must be command output, not a recollection (a run produced a "4 sentences" claim where the file had 3 — the milestone gate caught it).
- **pf-do / pf-auto**: a ticket that needs a secret is an immediate blocker — subagents and headless runs cannot call the secret helper. Such tickets are not sent through the fix loop; they are flagged "needs an interactive session" and, when known in advance, kept out of the waves entirely.
- **pf-auto**: a working-tree hygiene check between waves.
- Verified in the sandbox: milestone gating (one reviewer over three independent batches, caught a false claim), executor behaviour on contradictory criteria / missing source material / unavailable secrets (three correct BLOCKEDs, nothing invented), and orchestrator continuity — a successor given only the HANDOFF restored the goal, the registry, the exact next step and the blockers, and spotted the uncommitted tail the orchestrator had missed.
