# pf-replan — изменение курса без потери сделанного

Посреди выполнения появилась новая идея или решение поменялось. Два запрещённых рефлекса: продолжать по инерции («жалко сделанного») и переделывать всё с нуля. Правильный путь — оценить влияние и править точечно.

## Шаги

1. **Мини-допрос** (1–3 вопроса по правилам pf-spec): что именно меняется и почему; это новое требование сверху или отмена уже принятого решения?
2. **Трассировка влияния** — по цепочке «спека → тикеты → коммиты»: найди разделы SPEC, которых касается изменение → тикеты, ссылающиеся на них (`spec:` во frontmatter) → их зависимые (`depends_on`). Это зона пересмотра; всё вне её не трогается.
3. **Классифицируй и покажи человеку отчёт** (ничего не менять до «ок»):
   - **A — аддитивное**: сделанного не касается → дописать SPEC + новые тикеты в хвост. Отката нет.
   - **B — меняет невыполненное**: done-тикеты валидны → невыполненные переписать или отменить (`status: cancelled`, причина — в «Результат»), SPEC поправить.
   - **C — инвалидирует сделанное**: часть done-тикетов противоречит новому решению → два варианта с ценой каждого: (1) откат их коммитов (`git revert`, список — из «Результата» тикетов) + новые тикеты; (2) тикеты-переделки поверх без отката. Покажи оба, рекомендуй дешёвый.
4. **После «ок»**: правь SPEC (+ запись в «Историю изменений»: дата, что, почему, класс A/B/C), помечай отменённые тикеты, создавай новые (по правилам pf-tickets), при C — откатывай коммиты строго по списку. Если ведётся HANDOFF (компаньон pf-handoff) — обнови: отменённое — в «Не делать» (§13).
5. **Журнал** (§10): что изменилось, класс, что отменено/откачено. Это защита от «почему тут всё не так, как в спеке?» через месяц.

## Почему откат дешёвый

Каждый тикет фиксирует свои коммиты в «Результате» → откат тикета = revert ровно его коммитов. Отсюда дисциплина: мелкие тикеты, коммит на тикет. Никогда не откатывай «весь проект назад», если можно откатить два тикета.

## Когда НЕ нужен

Мелкая правка внутри текущего тикета (уровень S) — просто сделай её и упомяни в «Результате». pf-replan — для изменений, задевающих спеку или чужие тикеты.
