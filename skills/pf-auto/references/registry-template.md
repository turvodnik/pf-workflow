# Шаблон реестра автопилота (.agents/runtime/autopilot-run.md)

Используется, когда компаньон pf-handoff не установлен (иначе реестр живёт в HANDOFF). Перезаписывается на каждом событии: волна запущена, сводка принята, вердикт ревью, раунд фикса, стоп. Время событий — только по `date` (не «на глаз»: оркестратор 11–12.09 дважды завысил метки на ~1 ч).

```markdown
# Реестр автопилота · <проект> · <дата>
session_id: <полный id из строки старта «Сессия: <id> — это значение поля session_id в HANDOFF/реестре» — по нему Stop-хук wait-guard.sh отличает свой реестр от чужого>

Параметры: fix_rounds=3, parallel=2, batch=1–3. BASE волны <N>: <sha>.

| Задание | Тикеты | Субагент (модель/усилие) | Worktree | sha | fix_rounds | Маркер препасса | Статус |
|---|---|---|---|---|---|---|---|
| A (волна 1) | T-001, T-002 | pf-executor (Sonnet, low) `a20842…` · pf-reviewer (Opus, medium) `aa239d…` | да | `<sha, переданный ревьюеру строкой SHA: в постановке>` | 0/3 | `<путь к файлу-маркеру из PENDING:>` / прочитан: OK|FAIL|SKIP / — | запущен / сводка принята / гейт: ЧИСТО|замечания / фикс-раунд N/3 / done / blocked |
| B (волна 1) | T-003 | pf-executor (Sonnet, low) `aa81e7…` · pf-reviewer (Opus, medium) `a0d950…` · раунд 3 pf-executor (Opus, high) `afa4f2…` | нет | `<sha>` | 3/3 · fuse tripped | не ревьюировано (маркер не прочитан) | … |
| C (волна 2) | T-004 | — | — | — | — | — | ждёт A; [стоп-граница: <какое внешнее действие>] |

`session_id` — полный id из строки «Сессия: …» в начале контекста сессии оркестратора, без сокращения (свой реестр — точное совпадение; старое значение из 8 знаков хук ещё признаёт, если оно однозначно): строку печатает хук старта pf-handoff, а без pf-handoff — хук pf-workflow `hooks/pf-session-id.sh`. Заглушку не оставлять: с ней Stop-хук молча не охраняет реестр. Строки нет — `session_id: —` и пометка в реестре «страж ожидания выключен».

Субагент — роль, модель и id запуска: `agentId` субагента, PID внешнего процесса или маркер `council.sh` (`PENDING: <маркер>`). Строка пишется СРАЗУ после запуска, а не при сводке: после сжатия только по ней родитель свяжет уведомление о завершении с заданием (pf-handoff, «Milestone handoff»). Worktree — «да», если исполнитель запущен с `isolation: worktree` (другая живая сессия в репозитории или >1 исполнителя в волне). Колонка `sha` — SHA ветки исполнителя, снятый ПОСЛЕ сводки и переданный ревьюеру строкой `SHA:` в постановке (шаблон 2 dispatch-templates.md); гейт сверяет его с `git rev-parse HEAD` в ревью. `fix_rounds` — счётчик `N/3`: 0 при запуске, +1 на каждый фикс-раунд (pf-auto шаг 5); на 3-м без «ЧИСТО» — обязательный `blocked` и пометка `fuse tripped` в этой же ячейке (I-026). Маркер препасса — путь из `PENDING: <маркер>` (`--async`); `done` не ставится, пока маркер не прочитан через `--wait`; та же ячейка несёт и evals-smoke (pf-auto шаг 4, T-146) через « / » рядом с Codex-маркером — `evals smoke: N/M | skip | partial | unavailable`. Тесты волны — в строке задания последнего исполнителя волны: счётчики passed/failed + `saved:`-путь полного лога из `pf-run.sh` («Output diet», pf-auto шаг 3) — простыня вывода в реестр не копируется.

## Запарковано (💭 — решает финальный ревью/отчёт)
1. <замечание> — <откуда>

## Стопы
- <время> · <причина стопа> · <что подготовлено> · ждёт человека
```
